# 英語ボトルネック診断 LP

Meta / Instagram 広告 → 診断 → LINEで詳細レポート → 無料カウンセリング の導線用ランディングページ。
ビルド不要の静的1ファイル構成です。

## デプロイ（GitHub → Vercel）

```bash
git init
git add index.html README.md
git commit -m "英語ボトルネック診断 LP v1"
git branch -M main
git remote add origin git@github.com:<org>/<repo>.git
git push -u origin main
```

Vercel → Add New → Project → 該当リポジトリを Import。
Framework Preset は **Other**、Build Command と Output Directory は**空のまま**で Deploy。

## 公開前に設定が必要な箇所

`index.html` 冒頭の `CONFIG` を編集してください。

| キー | 内容 |
|---|---|
| `LINE_URL` | LINE公式アカウントの友だち追加URL（例 `https://lin.ee/xxxx`） |
| `COUNSELING_URL` | 無料カウンセリング予約URL |
| `WEBINAR_URL` | ウェビナー申込URL。`null` ならボタン非表示 |
| `WEBHOOK_URL` | 回答データの送信先。`null` なら送信しない |
| `CUSTOMERS` | 累計受講者数の表示値（**要確認**：eBook 25,000人／公式サイト 12,000名で不一致） |
| `PRICE_*` | 受講料。改定時はここだけ直せば全文に反映されます |

## 画面構成の方針

結果ページは **「どこが詰まっているか」と「症状」までしか見せない**。
メカニズム・時間配分・費用リフレーミング・投資レポートは **LINEで送るPDF側** に置く。
結果ページで全部語ると、LINEで送る中身が無くなり、友だち追加の理由が消えるため。

| 場所 | 内容 |
|---|---|
| 結果ページ | タイプ宣告／5ステップ図／土台・発揮率／症状3つ／やるべきトレーニング名だけ |
| PDF（LINE） | メカニズム解説／効かなかった理由／時間配分／3時間の作り方／投資レポート |
| LINEステップ配信 | 費用リフレーミング（270時間の比較、月額の対比）→ カウンセリング |

PDFの原稿は `index.html` 内の `T`（タイプ定義）と `WHY`（学習法別の理由）に入っている。
ページ表示には使っていないが、単一の情報源にするため同居させている。
※ページのソースを見れば読めてしまう点は許容している。隠す場合はサーバ側へ移すこと。

## 診断ロジック

- **16問**。設問数は「答えやすいか」で決めており、14問は即答できる頻度・程度スケール。
  残る2問（字幕／紙に書けるか）だけが数秒考える設問で、これが弁別質問。
- **TOEICのスコア帯**が唯一の客観指標。他の自己申告設問のアンカーになるため序盤に置く。
  「受けたことがない」はスコアを持たせない（推測させると精度が落ちる）。
- 複数選択は3問（つまずき方／続かない理由／学習法）。併存が普通な設問を単一選択にすると
  回答が歪むため。ただし**弁別質問2問は単一選択のまま**にする（複数選択にすると判定が割れる）。
- つまずき方は `agg:'min'` で「最も重い症状」を採用する（平均だと症状が薄まる）。
- サブスコアは K（知識DB）P（音声知覚）U（意味理解）C（概念化）F（文章化）V（音声化）T（投下時間）。
- ボトルネック判定は**最低点ではなく最上流**。5ステップは直列なので、上流が詰まっていれば
  下流の低スコアは見かけにすぎないため（制約理論）。判定順は K→P→U→C→F→V。
- 閾値は `score()` 内の `if(S.K<45)...` を編集して調整します。運用2週間でタイプ分布を見て
  1タイプが60%を超えていたら閾値が不適切なので調整してください。
